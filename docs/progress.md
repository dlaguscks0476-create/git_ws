# 진행 체크리스트와 작업 기록

현재 상태: **계획 수립 완료 · 장비 검증 및 구현 시작 전**<br>
기준 계획: [프로젝트 계획서](project-plan.md)<br>
작업 시간: 하루 3~4시간, 3주·15작업일을 기준으로 진행한다.

작업일은 실제 작업한 날을 뜻한다. 면접·지원 일정이나 환경 문제에 따라 이동하며, 날짜보다 각 단계의 완료 증거를 우선한다. 체크는 실행 결과와 기록을 확인한 뒤 표시한다.

## 시작 전 확인

- [x] 보유 장비 정보 확인: Raspberry Pi 4B 4GB, 공식 8M 카메라, 32GB SD카드, Ubuntu 24.04 노트북·RTX 5070 Ti, 보조 Galaxy S22.
- [x] 프로젝트 범위·역할 분담·3주 일정·실험 및 완료 기준 수립.
- [ ] Pi OS 설치와 실제 카메라 모델·구동 확인.
- [ ] 노트북 CUDA 연산 및 GPU 모델 추론 확인.
- [ ] Pi와 노트북 사이 ROS2 통신 확인.
- [ ] 기본 성능 측정과 FPS·복구시간 목표 결정.

장비 정보는 제공받은 사양이며, 실제 동작을 검증한 결과가 아니다. OS 설치, 카메라 입력, GPU 추론, 통신, 성능 실측은 아직 완료하지 않았다.

## 1주차 · 환경 확인과 기본 연결

- [ ] **1일차 — 환경 준비**: 노트북의 OS·ROS·NVIDIA 드라이버·Python 환경을 기록하고, Pi 전원·카메라 보드·SD카드를 확인한다. Pi OS와 ROS2 설치를 시작한다.
- [ ] **2일차 — 독립 동작 검증**: 카메라 프레임 취득, Pi↔노트북 ROS 통신, CUDA 텐서 연산과 경량 YOLO 단일 이미지 추론을 확인한다. 성공·실패 명령과 버전을 남긴다.
- [ ] **3일차 — 영상 발행**: 선택한 입력에서 프레임을 얻어 Pi에서 `CompressedImage`로 발행한다. 해상도·JPEG 품질·발행 FPS를 설정 파일로 관리한다.
- [ ] **4일차 — 탐지 연결**: 노트북에서 영상을 수신하고 탐지 화면과 `Detection2DArray` 결과 토픽을 확인한다.
- [ ] **5일차 — 실행 구성 정리**: 장비별 launch와 예시 설정, 종료 처리를 정리하고 카메라→Pi→노트북 탐지 데모를 남긴다.

**1주차 종료 증거:** 선택한 입력 경로, 환경·버전 기록, ROS 토픽 확인 결과, 첫 탐지 시연.

첫 이틀의 작업 시간 안에 CSI 카메라 프레임을 얻지 못하면 원인을 기록하고 S22→Pi 입력으로 전환한다. 이후 한 입력 방식에 집중한다. GPU 문제가 남으면 CPU로 노드 구조 개발을 이어가되, GPU 검증은 별도 미완료 항목으로 유지한다.

## 2주차 · 안정화와 비교 실험

- [ ] **6일차 — 최신 프레임 처리**: 수신과 추론을 분리한다. 처리 중인 프레임 외에 대기 프레임은 최신 1장만 유지하고 덮어쓰기 횟수를 기록한다.
- [ ] **7일차 — 중단 감지와 복구**: 입력 상태·timeout·재시도를 구현한다. 중단 화면 표시, 복구 시 대기 프레임 비우기, 이전 연결의 추론 결과 차단을 확인한다.
- [ ] **8일차 — 측정 기능**: 처리 단계 시간, 입력·발행·수신·추론 FPS, payload, CPU·메모리를 CSV로 남긴다. 첫 측정에 근거해 성능·복구시간 목표를 확정한다.
- [ ] **9일차 — QoS 실험**: 발행·구독 설정을 함께 맞춰 `BEST_EFFORT`/`RELIABLE`과 depth 1/10을 비교한다. 실행별 설정·원시 로그를 보관한다.
- [ ] **10일차 — 압축·과부하 실험**: JPEG 품질 60/80/95를 비교하고, 추론 지연을 추가했을 때 대기 프레임 상한과 정상 복귀를 확인한다.

**2주차 종료 증거:** 상태 전이·프레임 교체 검증, 기본 계측 CSV, 설정별 반복 실험 로그.

비교 실험은 같은 장면·모델·연결 조건에서 설정별 워밍업 15초 후 60초 측정을 3회 반복하는 것을 시작 기준으로 한다. 서로 다른 장비의 monotonic 시각을 빼지 않으며, GPU 처리시간은 실제 연산 완료 시점까지 측정한다. 미측정 항목은 미측정으로 표시한다.

## 3주차 · 최종 시험과 포트폴리오 정리

- [ ] **11일차 — 통합 시험**: 10분 연속 실행, 소프트웨어 입력 중단 10초·3회, 네트워크 단절 10초·3회, 추론 과부하 30초, 노트북 추론 노드 재시작을 시험한다. 복구 후 새 프레임 처리와 오래된 결과 표시 여부를 확인한다.
- [ ] **12일차 — 결과 분석**: 평균·p95·표본 수·측정 조건을 정리하고 그래프와 장애 시험표를 만든다. 선택한 설정의 근거와 측정 한계를 적는다.
- [ ] **13일차 — 재현 확인**: README에 설치·모델 준비·장비별 실행 명령을 정리하고, 실제 환경에서 문서 순서대로 재실행한다. 의존성·버전·설정 누락을 보완한다.
- [ ] **14일차 — 시연과 설명**: 실제 구성도를 갱신하고 약 1분 시연 영상을 만든다. 본인이 구현한 부분, 문제 해결 과정, 성능 절충을 정리한다.
- [ ] **15일차 — 첫 버전 마무리**: 아래 완료 기준과 미해결 사항을 점검한다. README 상단에 실제 결과와 시연을 배치하고 첫 릴리스를 정리한다.

**3주차 종료 증거:** 비교 그래프, 장애 시험표, 재현 가능한 실행 문서, 실제 구성도, 시연 영상, 첫 릴리스.

## 첫 버전 완료 기준

- [ ] 실제 Pi 경유 구성에서 GPU 객체 탐지와 결과 토픽 발행이 동작한다.
- [ ] 추론 과부하에도 대기 프레임은 최대 1장이며 오래된 영상이 누적 재생되지 않는다.
- [ ] 기본 설정으로 10분 연속 실행하고 FPS·자원·오류 로그를 확보한다.
- [ ] 입력 중단과 네트워크 단절 후 자동으로 새 영상을 처리하며 이전 결과를 정상 화면처럼 표시하지 않는다.
- [ ] 비교 실험의 설정·원시 CSV·분석 방법·결과와 측정 한계를 남긴다.
- [ ] README·구성도·실행 방법·약 1분 시연 영상으로 동작을 설명할 수 있다.
- [ ] 목표와 실측을 구분하고 미해결 문제·지원하지 않는 범위를 명시한다.
